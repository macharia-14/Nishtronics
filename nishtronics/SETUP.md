## Step 1 — Set Your Real Contact Details

Run once from the project root (needs Python 3):

```
python tools/set-contact.py 254712345678 --instagram https://instagram.com/yourshop --facebook https://facebook.com/yourshop
```

This updates the WhatsApp number, the phone number text and the social links in every page and in `js/`. Safe to re-run. Social flags are optional. If you have no Facebook or Instagram page yet, delete those icon links from the footers rather than leaving the generic homepage links.

The site shows no email address. Customers reach you by WhatsApp and phone.

## Step 2 — Firebase Setup (Optional but Recommended)

Without Firebase the public site still works from `data/products.json`, but **the admin panel requires Firebase** (there is no local password login). Firebase also stores orders and bookings and lets you edit products without touching files.

### Create Firebase Project

1. Go to [console.firebase.google.com](https://console.firebase.google.com)
2. Click **Create a project** → name it `nishtronics-soundlabs`
3. Disable Google Analytics (not needed)

### Enable Firestore

1. In Firebase Console → **Build → Firestore Database**
2. Click **Create database**
3. Choose **Production mode** → select a region (e.g., `europe-west1` or `us-central1`)

### Create the one admin account

1. Firebase Console → **Build → Authentication → Get started → Email/Password → Enable**
2. **Users → Add user** with your own email and a strong password
3. Copy that user's **User UID**
4. **Authentication → Settings → User actions**: turn **off** "Enable create (sign-up)". Without this, anyone with your public API key can register an account.

### Set Firestore Rules

1. Open `firestore.rules` from this folder
2. Replace `PASTE_ADMIN_UID_HERE` with the UID from above
3. Firestore → **Rules** tab → paste the whole file → **Publish**

The rules let the public read products, let customers create (only) a validated order or booking, and allow everything else only for your admin UID. Orders/bookings are size-capped and shape-checked to limit spam. The rules have not been run against the Firebase emulator yet, so after publishing, place a test order and a test booking from the site and confirm they appear in the admin panel.

### Get Your Config

1. Firebase Console → **Project Settings** (gear icon) → **General**
2. Scroll to **Your apps** → click **Web** (`</>`)
3. Register app → copy the `firebaseConfig` object

### Paste Config into `js/firebase.js`

```javascript
const FIREBASE_CONFIG = {
  apiKey:            "AIza...",
  authDomain:        "nishtronics-soundlabs.firebaseapp.com",
  projectId:         "nishtronics-soundlabs",
  storageBucket:     "nishtronics-soundlabs.appspot.com",
  messagingSenderId: "12345678",
  appId:             "1:12345678:web:abc123"
};
```

### Seed Products to Firestore

1. Open `admin/index.html` in a browser
2. Sign in with the admin email and password you created above
3. On the Dashboard → click **"Seed Firestore from products.json"**
4. This uploads all 35+ products to Firestore (run once only)

## Step 3 — Admin Panel

**URL:** `yoursite.com/admin/index.html` (marked noindex, but not hidden; the Firestore rules are what protect your data)
**Login:** the Firebase email/password account from Step 2. Change the password under **Settings**.

### Admin Features
- **Dashboard** — product count, stock overview, quick actions
- **Products** — add/edit/delete products, toggle stock, update prices inline
- **Orders** — log WhatsApp orders, track status (New / Confirmed / Completed / Cancelled)
- **Bookings** — log booking requests, track appointment status
- **Settings** — change admin password

## Step 4 — Deploy for free (the domain is the only cost)

The site is static files, so it can be hosted for free on **Cloudflare Pages**. Firebase (free Spark plan) stores orders and runs the admin. You pay only for the domain.

### 1. Buy the domain
Buy a `.co.ke` from a Kenyan registrar. Compare the **renewal** price, not just the first-year promo, because international registrars charge several times more for `.co.ke`.

### 2. Before you upload (once)
1. `python tools/set-contact.py 2547XXXXXXXX --instagram <url> --facebook <url>`: your real number and pages.
2. Replace the gallery tiles in `images/gallery/` with photos of your own installs, and add product photos (see Images below).
3. `python tools/build-blog.py --site https://yourdomain.co.ke`: writes the sitemap and share tags for the real address.
4. Firebase (Step 2 above) is optional for launch. Without it the site works fully, customers order by WhatsApp, and the admin panel stays unavailable.

### 3. Pack the public files
```
python tools/make-dist.py --zip
```
This creates `dist/` (and `dist.zip`) with only what the site needs. It leaves out the tools, blog sources, setup notes and raw photos.

### 4. Put it online
**Fastest (drag and drop):** Cloudflare dashboard → Workers & Pages → Create application → Pages → Direct upload → name the project → drag in the `dist` folder (or `dist.zip`) → Deploy. You get a free `yourproject.pages.dev` address immediately. Every update means uploading `dist` again.

**Better if you will update often (GitHub):** put the project in a GitHub repository (the included `.gitignore` keeps raw photos out), then Workers & Pages → Create → Pages → Connect to Git. Build command `python3 tools/make-dist.py`, output directory `dist`. After that, pushing a change redeploys the site by itself. A Direct Upload project cannot be switched to Git later; you would create a new project and move the domain.

### 5. Connect your domain
1. Create a free Cloudflare account (you already have one) and **Add a site** with your domain, on the Free plan.
2. Cloudflare shows two nameservers. At your registrar, replace the domain's nameservers with those two. You do not transfer the domain.
3. In your Pages project: Custom domains → Set up a custom domain → enter `yourdomain.co.ke`. SSL is automatic. Also add `www.yourdomain.co.ke`.
4. Allow some time (minutes to a few hours) for the nameserver change to take effect.

### 6. After it is live
- Firebase console → Authentication/Firestore: nothing to change for the domain, but restrict the Firebase web API key to your domain in Google Cloud Console.
- Create a free Google Business Profile for the shop and link the new site.
- In Google Search Console, add the site and submit `sitemap.xml`.

### Updating the site later
Change a file, then (if you use drag and drop) `python tools/make-dist.py` and upload `dist` again; (if you use GitHub) commit and push. A blog post also needs `python tools/build-blog.py` first.

## Images

**Product images.** Every product already has a drawn illustration (`images/products/<id>.svg`, made by `python tools/make-product-art.py` from the product's type, size and brand). Real photos replace them automatically:

1. Put raw photos in `images/_incoming/` named after the product id, e.g. `kw-6x9-kfc1669s.jpg`
2. `pip install pillow` (once), then `python tools/prepare-images.py`
3. Compressed WebP files (max 800px, aim under 100 KB) land in `images/products/<id>.webp` and `images/products/index.json` is updated, so the site uses the photo for that product and the drawing for the rest.
4. `python tools/prepare-images.py --missing` lists products still using a drawing.

Deploy `images/products/`, `images/bg/` and `images/gallery/`; do **not** upload `images/_incoming/`. An explicit `image` value on a product (path or URL) overrides all of this. Re-run `make-product-art.py` after adding products to get their drawing.

**Backgrounds and gallery tiles are generated artwork, not photos.** `images/bg/*.webp` (page headers, section backgrounds, service cards) and `images/gallery/*.webp` are audio-themed illustrations made for this site. In light mode the files in `images/bg/` are inverted by CSS to a light version, so a real photo should live **outside** `images/bg/` (or carry a `data-photo` attribute on its `<img>`) to be shown as-is.

The gallery heading says "Real jobs. Real results": replace the tiles in `images/gallery/` with photos of your own installs, and update the captions to match, before relying on that claim.

**Updating images, quick reference** (after any change: `python tools/make-dist.py`, then upload `dist` again or push to GitHub)

| What | Put the raw photo in | Run | Result |
|---|---|---|---|
| Product photo | `images/_incoming/<product-id>.jpg` | `python tools/prepare-images.py` | `images/products/<id>.webp`, used instead of the drawing |
| Gallery tile | `images/_incoming/gallery/<tile-name>.jpg` (e.g. `gal-car-1.jpg`) | same | replaces `images/gallery/<tile-name>.webp`, cropped 4:3 |
| Blog cover | `images/_incoming/blog/<post-name>.jpg` | same | replaces `images/blog/<post-name>.webp`, cropped 1200x630 |

Gallery captions live in `gallery.html` and `index.html`, so edit those when you swap a tile.

## Blog

The blog is plain static pages, so it is fast and search engines can read every post. Posts are markdown files in `content/blog/`; a script turns them into pages.

**Add a post**

1. Create `content/blog/my-new-post.md` (copy an existing one). The top of the file looks like:

```
---
title: My new post
date: 2026-11-20
category: Guides
excerpt: One or two sentences for the cards and search results.
cover: images/blog/my-new-post.webp
---
Your text in simple markdown.
```

2. Optional: put a 1200x630 image at the `cover` path. Without one, a default cover is used.
3. Run `python tools/build-blog.py`. It rewrites `blog.html`, every page in `blog/`, and the "Sound Advice" block on the home page (the three newest posts).
4. Deploy the project as usual.

**Writing**: `## headings`, `**bold**`, `*italic*`, `[links](products.html)`, `- bullets`, `1. numbered lists`, `> quotes`, `| tables |`. Write `{{wa}}` in a link to insert your WhatsApp number (`[message us](https://wa.me/{{wa}})`). Link to other posts by file name (`sealed-vs-ported-subwoofer.html`).

**After you deploy to a real domain**, run `python tools/build-blog.py --site https://yourdomain.co.ke`. That also writes `sitemap.xml`, `robots.txt` and `feed.xml` and adds canonical and social-share tags. Submit the sitemap in Google Search Console.

**Changing the menu or your phone number**: run `python tools/sync-nav.py` (menu) and `python tools/set-contact.py` (number), then `python tools/build-blog.py` again so the blog pages pick up the change. The menu is defined once, in the `LINKS` list at the top of `tools/sync-nav.py`.

The six starter posts are general advice written for this site. Edit them to match how you actually work, and change their dates, before relying on them. The `cover` images are generated artwork, like the other backgrounds.

## Customising Products

Without Firebase, edit `data/products.json` directly. Each product has:

```json
{
  "id": "unique-id",
  "name": "Kenwood KFC-W3016 12\" Sub",
  "brand": "Kenwood",
  "category": "subwoofers",
  "subcategory": "12inch",
  "price": 12500,
  "description": "Short description…",
  "specs": { "Power": "1500W", "Impedance": "2 Ohm" },
  "badge": "bestseller",
  "inStock": true
}
```

(`image` is optional; see Product Photos.)

**Categories:** `speakers`, `subwoofers`, `headunits`, `amplifiers`, `accessories`, `trackers`, `secondhand`

**Badges:** `bestseller`, `new`, `popular`, `high-end`, `2nd-hand`, `custom`

## Design System Notes

- **Themes:** dark by default; `body.theme-light` switches to a warm ivory palette. All colours are tokens at the top of `css/style.css` (`--ink`..`--ink-4`, `--line`, `--t1`..`--t3`, `--gold`, `--on-gold`). Never hard-code a colour in a page; use a token.
- **Always-dark pieces:** only image hover overlays and the lightbox force dark tokens, so their light text stays readable in light mode. Everything else, including the hero, photo sections and the footer, follows the theme. To make a new element stay dark, give it the `on-dark` class. The footer colour is the `--footer-bg` token.
- **Diagonal cuts:** wedges use `--page` (the current theme's page colour). If a photo section follows a plain section with a different background, set `style="--cut:var(--page-1)"` on the photo section so the wedge matches.
- **Fonts:** Barlow Condensed (headings) + Outfit (body) + Space Mono (numbers/prices)
- **Icons:** one SVG sprite in `js/icons.js` (see the `i-` ids); no emoji anywhere in the UI.
- **Buttons/labels:** sentence-case buttons and chips; small uppercase is kept only for section kickers and form section titles.
- **Product badges:** classes `b-gold`, `b-green`, `b-blue`, `b-purple`, `b-orange`, `b-teal` match `BADGE_MAP` in `js/main.js`.
- **Music theme:** a vinyl record (injected into `.hero`/`.page-hero` by `js/main.js`, spins slowly, stops under reduced-motion), a waveform under every section heading, `01 02 03` track numbers on section kickers and service cards (pure CSS counters), VU meters on speaker/sub/amp cards (log scale of the RMS figure in `products.json`; head units are excluded because their wattage is a different measure), and an equalizer skyline on top of the footer.
- **Animations:** `.reveal` class + IntersectionObserver for scroll-triggered entries
- **Cart:** Slide-in panel triggered from nav, no page reload needed
